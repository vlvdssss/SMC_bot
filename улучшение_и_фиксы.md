## 🔴 ПРОБЛЕМА #1: Бот не входит в сделки при получении сигналов

### Описание
Сигналы от AI приходят и регистрируются, но бот их скипает и не открывает позиции.

### Наблюдаемое поведение
- ✅ Сигналы генерируются AI анализом
- ✅ Сигналы записываются в систему
- ❌ Бот НЕ открывает сделки
- ❌ Позиции остаются пустыми

### Специфика по инструментам
- **XAUUSD (золото)**: Сильное подозрение, что бот вообще не видит этот инструмент
- **EURUSD**: Предположительно видит, но требуется проверка

### Ожидаемое поведение
- Сигнал приходит → бот проверяет условия → открывает позицию по сигналу
- Если есть блокирующие условия → логирует причину отказа

### Зоны проверки (без исправлений!)

#### 1. Конфигурация инструментов
- Файл: `config/instruments.yaml`
- Проверить:
  - Включен ли XAUUSD (`enabled: true`)
  - Включен ли анализ (`analysis_enabled: true`)
  - Включена ли торговля (`trading_enabled: true`)
  - Корректный ли symbol name (может быть `XAUUSD` vs `XAU/USD` vs `GOLD`)

#### 2. MT5 подключение и доступность символов
- Проверить: Видит ли MT5 connector символ XAUUSD
- Проверить: Есть ли XAUUSD в списке доступных символов MT5
- Проверить: Корректный ли volume (lot size) для XAUUSD
- Логи: Ошибки типа "Symbol not found" или "Invalid volume"

#### 3. Маршрутизация сигналов
- Путь сигнала: AI → SignalManager → Executor → MT5
- Проверить каждый этап:
  - AI генерирует сигнал для правильного символа?
  - SignalManager получает сигнал?
  - SignalManager триггерит сигнал (time/conditions)?
  - Executor получает команду на открытие?
  - MT5 connector пытается открыть позицию?

#### 4. Блокирующие условия
- Risk Manager может блокировать сделки
- Time restrictions (night/weekend blocks)
- Position limit (max positions)
- Trading blocks (AI warnings/blocks)
- Account balance/margin requirements

#### 5. Логи для анализа
- `logs/baza_*.log` - ищем строки:
  - `[SIGNAL]` - сигналы приходят?
  - `[TRADE]` - попытки открытия позиций?
  - `[ERROR]` - ошибки при открытии?
  - `[MT5]` - ответы от MT5 терминала?
  - Фразы: "skipping", "blocked", "denied", "failed"

## 🔴 ПРОБЛЕМА #2: Некорректная обработка сигнала + дублирование сделок

### Описание
Сигнал ведёт себя нестабильно: сначала не записывается, потом появляется, а после перезапуска бот открывает 2 сделки одновременно и входит НЕ по точке входа.

### Наблюдаемое поведение
**Сценарий 1 - Пропадающий сигнал:**
- Сигнал пришёл от AI
- Не записался в активные сигналы
- Потом внезапно появился (timing issue?)

**Сценарий 2 - Неправильный вход:**
- После полного перезапуска программы
- Бот открыл сделку НЕ с точки входа (entry_price игнорируется?)
- Бот просто открыл в сторону сигнала (BUY/SELL)
- Бот открыл **2 сделки одновременно** (дубль!)

### Ожидаемое поведение
- Сигнал сохраняется один раз и не дублируется
- Сигнал триггерится ТОЛЬКО когда цена достигает entry_price
- Открывается ТОЛЬКО 1 сделка на 1 сигнал
- После перезапуска бот НЕ должен заново обрабатывать старые сигналы

### Зоны проверки (без исправлений!)

#### 1. Сохранение сигналов
- Файл: `data/ai_signals/active_signals.json`
- Проверить:
  - Сигналы сохраняются корректно?
  - Есть ли race condition при записи?
  - Есть ли дубликаты сигналов в файле?
  - Корректный ли формат timestamp?

#### 2. Механизм предотвращения дублей
- Код: Должен быть механизм "один сигнал = одна сделка"
- Проверить:
  - Есть ли проверка `signal.is_triggered` перед открытием?
  - Есть ли проверка `signal.is_filled` после открытия?
  - Обновляется ли статус сигнала после обработки?
  - Фильтруются ли уже обработанные сигналы при загрузке?

#### 3. Логика триггера сигнала
- Условие: Сигнал должен триггериться когда price ≈ entry_price
- Проверить:
  - Есть ли проверка `current_price` vs `entry_price`?
  - Какой tolerance используется? (±5 pips?)
  - Или бот игнорирует entry_price и открывает по market?

#### 4. Обработка после перезапуска
- При старте бот загружает активные сигналы из файла
- Проверить:
  - Фильтруются ли старые/expired сигналы?
  - Проверяется ли, что сигнал уже не обработан?
  - Есть ли защита от повторной обработки?

#### 5. Лимит количества позиций
- В v1.3.1 был добавлен механизм "max 1 position"
- Проверить:
  - Работает ли проверка перед открытием?
  - Проверяется ли текущее количество открытых позиций?
  - Блокируется ли открытие второй сделки?
  - Логируется ли причина блокировки?

#### 6. Логи для анализа
Искать последовательность:
```
[SIGNAL] New signal received: XAUUSD BUY @ 2650
[SIGNAL] Signal saved to active_signals.json
[SIGNAL] Checking trigger conditions...
[SIGNAL] Price reached entry point: 2650.5 ≈ 2650.0
[SIGNAL] Triggering signal...
[TRADE] Opening position...
[TRADE] Position opened - BUY XAUUSD @ 2650.5
[SIGNAL] Signal marked as filled
```

Проверить аномалии:
- Двойная запись "Signal saved"
- Два "Opening position" подряд
- "Position opened" без "Triggering signal"

## 🟡 ПРОБЛЕМА #3: Фильтр новостей (временно отключается)

### Описание
Фильтр новостей на данном этапе НЕ используется и должен быть полностью отключен до устранения основных проблем.

### Текущий статус
- Модуль: `src/ai/news_filter.py`
- Статус: **Временно отключен**
- Причина: Не влияет на core функциональность входа в сделки

### Ожидаемое поведение
- Фильтр новостей НЕ блокирует торговлю
- Фильтр новостей НЕ влияет на принятие решений
- Можно полностью игнорировать новости на этапе отладки

### Зоны проверки (без исправлений!)

#### 1. Конфигурация
- Файл: `config/ai.yaml`
- Секция: `news_filter` или аналогичная
- Проверить: Есть ли флаг `enabled: false`?

#### 2. Использование в коде
- Проверить где вызывается:
  - `GPTNewsFilter`
  - `RealTimeNewsFetcher`
  - Методы с `news` в названии
- Убедиться что эти модули НЕ блокируют сделки

#### 3. Логи
- Искать строки с `[NEWS]` или `[FILTER]`
- Проверить: Не пишется ли "Trade blocked by news filter"

### Примечание
К фильтру новостей вернёмся после решения проблем #1 и #2.

## 🔴 ПРОБЛЕМА #4: Не работает Telegram

### Описание
Уведомления и логика Telegram Bot не функционируют.

### Наблюдаемое поведение
- ❌ Уведомления НЕ приходят в Telegram
- ❌ Команды боту НЕ работают
- Неизвестно: Инициализируется ли Telegram модуль вообще?

### Ожидаемое поведение
- Уведомления о сделках приходят в Telegram
- Статус бота можно запросить через команды
- Ошибки логируются если Telegram не подключен

### Зоны проверки (без исправлений!)

#### 1. Конфигурация Telegram
- Файл: `config/telegram.yaml`
- Проверить:
  - Заполнен ли `bot_token`?
  - Заполнен ли `chat_id`?
  - Включен ли Telegram (`enabled: true`)?

#### 2. Инициализация модуля
- Код: `src/monitoring/telegram_bot.py` или `telegram_notifier.py`
- Проверить:
  - Инициализируется ли класс при старте?
  - Есть ли успешное подключение к Telegram API?
  - Логируется ли "Telegram bot started"?

#### 3. Отправка уведомлений
- Проверить где вызываются уведомления:
  - При открытии позиции
  - При закрытии позиции
  - При получении сигнала
  - При ошибках
- Вызывается ли метод `send_message()` или аналогичный?

#### 4. Логи
- Искать строки:
  - `[TELEGRAM]` - инициализация, отправка
  - `Failed to send telegram` - ошибки отправки
  - `Bot token invalid` - проблемы с токеном
  - `Chat ID not found` - проблемы с chat_id

#### 5. Возможные причины
- Неверный bot_token (устарел/удалён)
- Неверный chat_id (не тот чат)
- Бот не добавлен в чат
- Telegram API недоступен (firewall/proxy)
- Модуль не инициализируется при старте
- Exceptions при отправке молча игнорируются

## 🟡 ПРОБЛЕМА #5: Трейлинг-стоп работает нестабильно или не работает

### Описание
Есть подозрения, что механизм трейлинг-стопа либо работает некорректно, либо вообще не активируется.

### Наблюдаемое поведение
- Неизвестно: Активируется ли трейлинг вообще?
- Неизвестно: Двигается ли стоп-лосс за ценой?
- Подозрение: Стоп может оставаться статичным

### Ожидаемое поведение
- После достижения определённого профита трейлинг активируется
- Стоп-лосс двигается за ценой, фиксируя прибыль
- При откате цены позиция закрывается с прибылью

### Зоны проверки (без исправлений!)

#### 1. Конфигурация трейлинга
- Файл: `config/portfolio.yaml` или `config/mt5.yaml`
- Проверить:
  - Включен ли трейлинг (`trailing_stop_enabled: true`)?
  - Какие параметры:
    - `activation_profit` - после какого профита включается?
    - `trailing_distance` - на каком расстоянии от цены?
    - `step` - с каким шагом двигается?

#### 2. Модуль трейлинга
- Код: Искать класс `TrailingStop` или методы `update_trailing_stop`
- Проверить:
  - Инициализируется ли модуль?
  - Вызывается ли update метод регулярно?
  - Есть ли логика проверки профита?
  - Есть ли логика обновления SL в MT5?

#### 3. Условия активации
- Проверить:
  - Когда трейлинг должен включиться? (profit > X pips?)
  - Проверяется ли текущий профит позиции?
  - Сравнивается ли с порогом активации?
  - Логируется ли момент активации?

#### 4. Обновление стоп-лосса
- Проверить:
  - Вызывается ли `MT5Connector.modify_position()`?
  - Передаётся ли новый SL уровень?
  - Возвращается ли успешный ответ от MT5?
  - Обрабатываются ли ошибки MT5?

#### 5. Частота обновления
- Проверить:
  - Как часто проверяется необходимость обновления SL?
  - Есть ли задержка/throttling?
  - Может быть слишком редко проверяется?

#### 6. Логи для анализа
Искать последовательность:
```
[TRAILING] Position profit: +15.5 pips
[TRAILING] Activation threshold reached: 15.5 > 10.0
[TRAILING] Trailing stop activated
[TRAILING] Moving SL from 2650.0 to 2655.0 (+5 pips)
[MT5] Position modified successfully
[TRAILING] New SL: 2655.0
```

Проверить:
- Есть ли эти логи вообще?
- Активируется ли трейлинг?
- Обновляется ли SL?
- Есть ли ошибки от MT5?

## 🎯 ПРОБЛЕМА #6: Переработка логики GPT-анализа (Decision Engine)

### Концепция изменений

**Текущая проблема:**
- GPT работает как аналитик, пишет объяснения для людей
- Возвращает большие JSON с текстовыми описаниями
- Даёт рекомендации и прогнозы
- Сложная обработка ответа

**Новая концепция:**
- GPT = Trading Decision Engine (движок принятия решений)
- Только машинные данные
- Минимальный ответ
- Без объяснений

---

### 6.1 Старая логика (ТЕКУЩАЯ)

**Роль GPT:**
```
- Анализирует рынок
- Описывает тренд
- Объясняет уровни поддержки/сопротивления
- Даёт рекомендации
- Пишет развёрнутый анализ на русском
- Возвращает массивы сигналов
```

**Формат ответа (старый):**
```json
{
  "summary": {...},
  "key_levels": {...},
  "signals": [...],  // Массив сигналов
  "analysis": {
    "trend": "Подробное описание...",
    "support_resistance": "Описание уровней...",
    "patterns": "Паттерны...",
    "entry_exit": "Точки входа...",
    "risk_assessment": "Оценка риска...",
    "news_impact": "Влияние новостей...",
    "recommendation": "Рекомендация..."
  },
  "risk_factors": ["Текст", "Текст"],
  "trading_blocks": {...}
}
```

**Проблемы:**
- Много лишнего текста
- Массивы сигналов (неоднозначность)
- Сложная валидация
- GPT может "разговориться"
- Нестабильность парсинга

---

### 6.2 Новая логика (ПЛАНИРУЕТСЯ)

**Новая роль GPT:**
```
✅ Принять решение: BUY/SELL/NONE
✅ Вернуть параметры сделки
✅ Вернуть уровень блокировки

❌ НЕ объяснять причины
❌ НЕ описывать рынок
❌ НЕ давать рекомендации
❌ НЕ писать текст для человека
```

**Новый формат ответа (строго обязательный):**
```json
{
  "timestamp": "2026-01-21T12:00:00",
  "symbol": "XAUUSD",
  
  "decision": {
    "action": "BUY|SELL|NONE",
    "confidence": 85,
    "block": "NONE|SOFT|HARD"
  },
  
  "trade": {
    "entry": 2665.0,
    "stop_loss": 2660.0,
    "take_profit": 2675.0,
    "risk_reward": 2.0
  }
}
```

**Правила:**
- Если `action = NONE` → объект `trade` отсутствует
- Никаких массивов
- Никаких текстовых описаний
- Никаких объяснений
- Только машинно-обрабатываемые данные

---

### 6.3 Исключённые поля (удалить из кода)

**Удалить навсегда:**
```
- analysis (весь объект)
- reasoning
- recommendations
- risk_factors (текстовые описания)
- summaries
- описания новостей
- структурные комментарии
- trigger_time (заменён на TTL)
- массив signals (только один decision)
```

---

### 6.4 Новые правила принятия решения для GPT

**Обязательные условия в промпте:**

1. **Только один сигнал максимум**
   - Старый: массив signals
   - Новый: один decision

2. **Entry близко к текущей цене**
   - Максимум 10-30 пипсов от current_price
   - Если дальше → NONE

3. **Если цена прошла >50% к TP → NONE**
   - Проверка упущенной возможности
   - Не давать сигнал на уже ушедшую цену

4. **Решение ТОЛЬКО на текущий момент**
   - Никаких прогнозов "на 15:00"
   - Только immediate или NONE

5. **Недостаточная вероятность → NONE**
   - Если уверенность <70% → action = NONE
   - Лучше пропустить, чем ошибиться

## ⏱️ ПРОБЛЕМА #8: Новый жизненный цикл сигнала (TTL Logic)

### 8.1 Старая логика сигналов

**Как работает сейчас:**
```
1. GPT создаёт сигнал с trigger_time
2. Сигнал ждёт триггера (достижение цены)
3. Сигнал хранится до срабатывания
4. Может быть несколько сигналов одновременно
5. Нет чёткого TTL
```

**Проблемы:**
- Сигналы могут висеть долго
- Неясно когда обновлять анализ
- Несколько сигналов = путаница
- Старые сигналы не аннулируются

---

### 8.2 Новая логика (TTL-based)

**Жизненный цикл:**

```
START
  ↓
[Нажата кнопка Start]
  ↓
[Запрос GPT]
  ↓
[Получен decision]
  ↓
  ├─→ action = NONE → [Ждать 15 мин] → [Новый запрос GPT]
  │
  └─→ action = BUY/SELL
        ↓
      [Активен сигнал с TTL]
        ↓
        ├─→ Цена достигла entry ДО истечения TTL
        │     ↓
        │   [ВХОД В СДЕЛКУ]
        │     ↓
        │   [Сопровождение сделки]
        │     ↓
        │   [Закрытие: TP/SL/Trailing]
        │     ↓
        │   [НЕМЕДЛЕННО новый запрос GPT]
        │
        └─→ TTL истёк БЕЗ входа
              ↓
            [Аннулировать сигнал]
              ↓
            [НЕМЕДЛЕННО новый запрос GPT]
```

**TTL параметры:**
- Задаётся в настройках GUI
- Возможные значения: 30 мин, 1 час, 2 часа
- TTL применяется ТОЛЬКО до входа в сделку
- После входа TTL не используется

---

### 8.3 Критические изменения

**1. TTL Timer:**
```python
# Псевдокод
signal.created_at = now()
signal.ttl_minutes = config.get('ttl', 60)
signal.expires_at = now() + ttl_minutes

while signal.active:
    if now() > signal.expires_at:
        signal.cancel()
        request_new_gpt_analysis()
        break
    
    if price_reached_entry():
        enter_trade()
        break
```

**2. Блокировка новых сигналов:**
```python
# Пока есть активная сделка
if has_open_position():
    block_gpt_requests = True
    block_new_signals = True
```

**3. Автоматический перезапрос:**
```python
# После закрытия сделки
def on_position_closed():
    log("Position closed, requesting new GPT analysis")
    request_gpt_analysis()
```

### 8.4 Потенциальные баги и точки тестирования

**⚠️ КРИТИЧЕСКИЕ ТОЧКИ:**

1. **Одновременные сигналы**
   - Проверить: только 1 активный сигнал в любой момент
   - Тест: попытка создать 2 сигнала → должен блокировать

2. **Истечение TTL во время проверки цены**

3. **Закрытие сделки и немедленный запрос GPT**

4. **Перезапуск бота с активным сигналом**
   - Проверить: загружается ли TTL из файла
   - Проверить: пересчитывается ли оставшееся время

5. **GPT запрос во время активной сделки**
   - Должен быть полностью заблокирован
   - Тест: попытка ручного запроса → отказ

1. **Нормальный flow:**
   - Start → GPT → BUY signal → Entry → TP → New GPT

   - Start → GPT → BUY signal → Wait TTL → Expire → New GPT

3. **Immediate NONE:**
   - Start → GPT → NONE → Wait 15min → New GPT
   - Проверить: нет лишних ожиданий

4. **Close and restart:**
   - Open position → Close (TP) → Immediate GPT request
   - Проверить: запрос в течение 5 секунд

5. **Blocked requests:**
   - Open position → Try manual GPT → Blocked
   - Проверить: отказ с логом

6. **GPT error handling:**
   - GPT timeout → Retry 3 times → Fallback
   - Проверить: не зависает бот

7. **Multiple close events:**
   - Close position → MT5 sends 2 events → Only 1 GPT request
   - Проверить: нет дублей
